# Documentação e manutenção

- Mantenha documentação coerente com o código e o banco reais.
- Em toda nova funcionalidade ou alteração de regra, comportamento, arquitetura, API, banco de dados, integração ou validação, revise quais documentos foram afetados e atualize-os no mesmo trabalho, antes de concluir.
- Atualize o documento temático correspondente para detalhes técnicos, contratos, regras ou procedimentos que orientem futuras alterações.
- Atualize o `README.md` quando a mudança afetar informações gerais necessárias a quem usa, configura, executa ou entende o projeto; não o use para duplicar detalhes já cobertos por documentos temáticos.
- Se nenhuma documentação precisar mudar, registre o motivo no relato final; não faça alterações documentais sem relação com o escopo.
- Não duplique instruções entre `AGENTS.md` e `docs/project`; o primeiro contém regras gerais e os segundos detalhes temáticos.
- Não crie documentação acadêmica em `docs/project`.
- Não invente exemplos que possam ser confundidos com dados reais.
- Ao concluir uma alteração, informe arquivos, banco afetado, validações e limitações.
